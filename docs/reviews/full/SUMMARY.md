## 2. Cross-cutting causes

Named as causes, not categories. Each explains findings that were filed independently.

### C1 — The wiring half of a two-half change is nobody's file, and nothing fails when it is missing

A value is computed, documented with the reason it matters, given a parameter — and the call site
that would supply it is in a different file owned by a different slice, and was never edited. This
is charter §3 and it is the largest cluster in the review.

Explains: persistence F1 (`updateLibraryExclusion(nil)`, with a comment describing this exact bug as
its justification), persistence F2 (`v9_tasteContribution` never backfilled — 945 of 945 rows on the
real file), library-ui §4 (`isComplete` "until the shell passes the real value"), library-ui §11
(`hasCredentials` "until batch 6"), library-ui §13 (`StackModel.isVisible` "not yet wired"),
library-ui §12 (`ShelfCard`, `visibleShelves`, `matchCount`, `shapeLine`, `Shelf.covers`), detail-ui
F4 (`coversFailure` set, never read), detail-ui F2 (`DetailBackdrop.height` declared, documented,
never applied), detail-ui F6 (`SeriesPager.selected` bound to `.constant`), third-parties #12
(`feedWorks:` parameter, sort rule and test for a path production never takes), shell F1
(`session.library.entries` filled only by `LibraryView`'s `.task`, read by Discover at launch),
reader N12 (`SeasonReading.describe`, no production caller).

### C2 — One flag carries three states, so "cancelled" and "not asked" render as "failed" or "empty"

Every screen has a two-valued loading flag and a nullable error, and there are three things to say:
still working, asked and failed, asked and empty. Cancellation is the fourth, and `APIError.cancelled`
is documented as never reaching a screen.

Explains: discovery D-2 (four "Cancelled" rows on a cold-launch tab switch, then four more requests),
discovery M-3, discovery B-1, detail-ui F9 (a cancelled cadence ask written as a failure row, so the
next open re-asks MangaUpdates), detail-ui F14 (`appleUnreachable: Bool` collapses offline/429/5xx/
decode), library-ui §2 (`isLoading` reused for "first page drawn", so the page-cap copy shows during
every healthy walk), library-ui §3 (the stale failure bar through the whole retry), shell F16
(`(try? history.count()) ?? 0` reads as "Nothing viewed yet"), persistence F12 (an empty-but-fresh
feed is indistinguishable from no cache), third-parties #13 ("Apple Books couldn't be reached" when it
was reached and had nothing), wire's three `CatalogueService` `try?` → nil sites.

### C3 — The account-change list is maintained by hand and has never been complete

`forgetPreviousAccount()` is a hand-written list of every account-scoped store. Each past bug added a
line. Its comment says the list *is* the test that the list is complete; it is not.

Explains: persistence F1 (the exclusion id is set to nil, never to the new account's id), persistence
F6 / third-parties #2 (the widget keeps the previous account's series, with tappable deep links),
persistence F7 (a failed `TasteLedger.clear()` swallowed), shell F17 (the display name survives
"Remove token"), reader N7 / tests T5 (a walk started before the invalidation commits the previous
account's library to memory and disk afterwards). History and the shelf surviving is the one item on
the list that is deliberate — which is why the others read as deliberate too.

### C4 — There is no shared third-party layer, so every politeness rule exists n−1 times

Nine clients, each with its own session, its own `Retry-After` parse, its own file cache, its own copy
of the User-Agent. `APIClient` has all of this once. No rule reached all nine.

Explains: third-parties #4 (nine clients on `URLSession.shared`: 60 s timeout, cookies accepted and
replayed to Webtoons and Shikimori), third-parties #6 + wire #2 (nine uncapped `Retry-After` parses; a
NaN silently ends spacing for the session, `1e300` traps in `humanDuration`), third-parties #14 (UA
declared twice, absent from four clients), third-parties #19 (seven copies of `Cached`/`file`/
`readCache`/`writeCache`, which is why the "expose `storedAt`" fix reached two of seven), detail-ui F3
(two `MangaUpdatesClient` actors, so the 3 s spacing the terms ask for is violated by construction on
every page open), third-parties #5 / detail-ui F11 (the one client with no cache).

### C5 — A long-lived actor is asked a whole-table question to answer a single-row one, and a per-frame `@State` is read by a whole subtree

Two shapes of one waste: the read that is O(library) when it needed O(1), and the state write that
invalidates a view tree when one child needed it.

Explains: reader N15 / detail-ui F18 (`cadenceEntry` decoded whole per page open), shell F9 (939
sequential actor hops on the launch path for links almost never cached), persistence F9 (the same feed
read and decoded twice per miss), persistence F11 (a 1.48 → 4.75 MB gunzip and 19,300-row decode to
label twelve cards), library-ui §8 (the whole shelf decoded on every Stack tab visit, before the first
request), reader N8 (the whole library re-absorbed into the taste ledger per series page open),
persistence F15 (19,300 rows re-filtered and re-sorted per offline page), detail-ui F15 (19 k scores
sorted to take 12), library-ui §10 (18 k `DisplayTitle.choose` + `Locale.preferredLanguages` per
keystroke), detail-ui F1 (`scrollOffset` as `@State` on `SeriesDetailView`: a Markdown parse, a tag
grouping, ~11 `Series.filling` copies and a model allocation per scroll frame), detail-ui F2/F12/F13,
discovery D-5, shell F12/F23, library-ui §19.

### Why none of the above failed a test

Not a sixth cause so much as why the first five survived. ~90 of ~125 source-tree reads are call-site
pins a same-named empty stub satisfies; the widget's JSON contract test round-trips the encoder's own
type, so renaming a field passes the test and breaks every widget forever (T2); one UI test has skipped
every run since a `textField` became a `searchField`, and a skip reads as green (T19); the fixtures for
`SeriesExtras`, `RecommendationStatus` and `LibraryChange` are the model's idea of a response; 13.5 s of
real sleeps stand in for synchronisation, two of them shorter than the debounce they race. And the one
script written for charter §1 has no caller.

## 5. The five highest-value changes

1. **Item 1 — set the library-exclusion id on sign-in** (`RootView+Session.swift:132`, one line).
   What the reader gains: recommendations stop suggesting series they already track, from the moment
   they enter a token rather than from the next relaunch. The repository's own doc calls this "the
   single largest source of 'these recommendations are bad'", and the comment beside the `nil`
   describes this exact bug as the reason the line exists. Best ratio in the review.
2. **Item 2 — backfill `tasteContribution`** (one migration). Measured on the real simulator file:
   945 `tasteSource` rows, 0 contributions. What the reader gains: removing a series from the library
   actually removes its tag weight. Today every series added before the v9 migration is permanent, so
   the ranker, the DNA strands and the stack's ordering are all built partly from series the reader
   deleted. The fix that shipped for this on 2026-09-13 was tested from an empty ledger — the number
   moved and the existing data did not, which is charter §5 exactly.
3. **Items 15 + 16 + 17 — the library walk's lifecycle** (one function and three lines). What the
   reader gains: an edit saved during the walk stays saved instead of silently reverting and being
   cached wrong for six hours; a signed-out account's library can no longer land on disk after the
   invalidation; and the export and import stop being one duplicated id away from a trap. Three
   defects, filed independently by four slices, all living in one page-accumulation loop.
4. **Items 21 + 22 + 14 + 8 — one third-party session and one back-off** (a file, a function and
   eleven small edits). What the reader gains: a hung `itunes.apple.com` stops holding the shelf
   skeleton for a full minute; a hostile or broken `Retry-After` stops trapping the failure screen and
   stops silently ending a client's spacing for the rest of the session; the app stops accepting and
   replaying Webtoons' and Shikimori's cookies, which is the one place its "sends nothing it did not
   choose to" claim is currently false; and the 3 s MangaUpdates spacing the terms ask for actually
   holds, which today it cannot, by construction, on every page open. This is C4 closed at its source
   instead of n−1 times.
5. **Items 3 + 47 + 48 + 40 + 26 — stop rendering `.cancelled` as a failure** (about six lines across
   four screens). What the reader gains: switching tabs or tapping "Pick back up" in the first second
   of a cold launch stops filling Discover with four "Cancelled" cards and then issuing four more
   requests; a superseded blend stops flashing a Retry; typing a publisher name stops flashing "Could
   not search publishers"; and popping a series page stops costing a MangaUpdates request on the next
   open. `APIError` documents this case as "never meant to reach a screen — callers drop it silently";
   four screens reach it.
